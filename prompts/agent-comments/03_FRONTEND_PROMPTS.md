# ЧАСТЬ A. Движок muya

## Epic F-1 — Публичный API muya для комментариев

Сейчас подсветка диапазонов есть только у поиска (`packages/muya/src/search/index.ts`): она
передаётся в `block.update(cursor, highlights)` и пропадает при следующей перерисовке блока.
Публичного API для выделения внутри блока и безголового разбора markdown в блоки нет.

### F-1.1 — Текстовые блоки и выделение

**Шаги реализации:**

1. `muya.getTextBlocks(): ITextBlockInfo[]` — все листовые контент-блоки в порядке документа:
   `{ index, type, text }`, где `text` — markdown-источник блока (то, что лежит в `block.text`),
   `type` — `paragraph` | `atxheading` | `setextheading` | `listitem` | `taskitem` | `tablecell` |
   `codeblock` | … (возьми имена из реестра блоков).
2. `muya.getSelectionInBlock(): { index, start, end, text } | null` — `null`, если выделение пустое
   или его концы в разных блоках (D8).
3. Безголовая функция `markdownToTextBlocks(markdown, options?)` в публичном экспорте
   `src/index.ts`. Она строит тот же список через `markdownToState` без DOM. Инвариант:
   `markdownToTextBlocks(muya.getMarkdown())` и `muya.getTextBlocks()` совпадают по `type` и `text`.

### F-1.2 — Постоянный слой декораций

**Шаги реализации:**

1. `muya.setDecorations(decorations: IDecoration[])`, где
   `IDecoration { id: string, blockIndex: number, start: number, end: number, active: boolean }`.
   Хранится на уровне редактора и применяется **при каждой** перерисовке блока, вместе с
   подсветкой поиска, а не вместо неё.
2. Расширь `IHighlight` необязательными `className` и `dataId`; inline-рендерер оборачивает
   диапазон в `span.mu-comment` (`.mu-comment-active` для активного) с `data-comment-id`.
   Пересечение с подсветкой поиска не ломает разметку: диапазоны режутся на непересекающиеся куски.
3. Событие `decoration-click` (`{ id }`) через `eventCenter` при клике по `span.mu-comment`.
4. `muya.scrollToDecoration(id)`.
5. `setContent` и смена документа сбрасывают декорации (как `search.reset()`).

**DoD:** тесты в `packages/muya/src/**/__tests__/`: инвариант F-1.1.3 на наборе фикстур (абзацы,
заголовки, вложенные списки, задачи, таблицы, цитаты, код); `getSelectionInBlock` возвращает
`null` для выделения через два блока; декорация переживает ввод в том же блоке и сосуществует с
поиском; клик даёт `decoration-click`. `pnpm -C packages/muya lint`, `lint:types`, `test`,
`check-circular`, `test:spec` — зелёные, conformance не упала.

## Epic F-2 — Ядро привязки (`renderer/src/agent/anchoring/`)

Чистый TypeScript без DOM и Vue. Работает над `ITextBlockInfo[]` (F-1.1), поэтому одинаково
обслуживает WYSIWYG (`muya.getTextBlocks()`) и режим исходника (`markdownToTextBlocks(text)`).

### F-2.1 — Захват и поиск якоря

**Шаги реализации:**

1. `captureAnchor(blocks, { index, start, end })` → `Anchor` (00 §3.2): `quote` = срез текста блока,
   `prefix` и `suffix` — до `ANCHOR_CONTEXT_CHARS` символов в том же блоке, `blockHint = { type, index }`.
2. `resolveAnchor(blocks, anchor)` → `{ status: 'anchored', index, start, end } | { status: 'orphaned' }`:
   - кандидаты — все вхождения `quote` в текстах блоков (строгое сравнение, без нечёткого поиска);
   - 1 кандидат → привязан;
   - больше одного → оставить те, у которых текст перед вхождением оканчивается на `prefix`, а
     текст после начинается с `suffix`; если остался один → привязан;
   - если после фильтра по контексту осталось несколько, и ровно один из них в блоке с `blockHint`
     (тот же `type` и `index`) → привязан; иначе оторван (ТЗ §5.3: «однозначно»).
3. Пустая цитата при захвате — ошибка; при поиске — всегда оторван.

### F-2.2 — Сопоставление с исходником

**Шаги реализации:**

1. `locateBlocksInSource(markdown, blocks)` → для каждого блока диапазон строк и функция перевода
   смещения в тексте блока в `{ line, ch }` исходника. Последовательный поиск строк блока в
   исходнике с учётом префиксов контейнеров в начале строк (`> `, маркеры и отступы списков, `|`
   таблиц).
2. Используется для подсветки в CodeMirror (`markText`), для диапазона строк в сообщении агенту
   (D23) и для перевода выделения CodeMirror в `{ index, start, end }`. Выделение в исходнике,
   концы которого попадают в разные блоки или за пределы текста блока (например, на маркер списка),
   — команда недоступна (D8).
3. Если перевод не удался (редкий синтаксис) — подсветка всех строк блока, тред при этом считается
   привязанным.

**DoD:** unit-тесты `test/unit/specs/agent-anchoring.spec.ts`: уникальная цитата; повтор цитаты,
разрешённый контекстом; повтор без различающего контекста → оторван; цитата уничтожена правкой →
оторван; цитата пережила вставку текста до неё; перенос треда WYSIWYG → исходник → WYSIWYG
сохраняет диапазон; сопоставление с исходником для абзаца, многострочного абзаца в цитате, пункта
вложенного списка, задачи, ячейки таблицы, заголовка setext.

ответ доходит до агента (`permission-allow` и `permission-reject`); «Остановить» завершает ход
(№6); падение процесса показано ошибкой и «Повторить», повтор того же текста идёт в ту же сессию.

## Epic F-8 — Вкладка diff (Промпт 7)

**Шаги реализации:**

1. Diff — **виртуальная вкладка**, а не файл: не входит в список файловых вкладок `store/editor.ts`,
   не сохраняется, не участвует в буферном состоянии окна и в «закрыть все сохранённые». `tabs.vue`
   рисует её после файловых вкладок. Когда она активна, область редактора показывает `diffView`,
   а Muya и CodeMirror остаются смонтированными, но скрытыми (состояние документа и undo не
   теряются).
2. Источники: «Ход» — `mt::git::diff { paths: turn.changedPaths }`; «Вся рабочая копия» —
   `mt::git::diff {}`. Кнопка «Обновить».
3. `diff2html`: режимы «единый» и «рядом», список файлов слева, стили на CSS-переменных темы.
   Никаких кнопок принятия или отклонения.
4. Автооткрытие после `turn_finished` только при непустом `changedPaths` (D18); ссылка
   «Изменения хода (N)» открывает diff именно этого хода.
5. Большой patch (`truncated`) — пометка «показаны первые 5 МБ».

**DoD:** e2e: после хода fake-агента вкладка показывает только записанные в ходе пути
